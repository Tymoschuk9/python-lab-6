# Лабораторна робота №6
## Тема: Автоматизоване тестування Python-програм (pytest)
## Мета роботи
Набуття практичних навичок розробки автоматизованих тестувальних сценаріїв для програмного забезпечення мовою Python із використанням сучасного фреймворку `pytest`. Засвоєння методик побудови тестових фікстур (fixtures), мокування зовнішніх залежностей (за допомогою `unittest.mock.Mock` та `AsyncMock`), перевірки обробки виняткових ситуацій (failure paths, custom exceptions), тестування асинхронного коду, розрахунку покриття коду тестами (statement & branch coverage >= 80%), а також організації ізольованого імпорту/експорту даних (CSV/JSON).

---

## Опис алгоритму та архітектури (Варіант №3)

Для Варіанта №3 (**Інтернет-магазин**) реалізовано автономний модуль, що включає повний цикл обробки предметної області: від обліку складських залишків до фінансових розрахунків та асинхронного мокед-взаємодії з платіжним шлюзом.

### 1. Основні класи та структури даних:
* **`Money`** — незмінна (frozen) доменна модель грошових сум із валідацією на від’ємні значення, підтримкою арифметичних операцій (`+`, `-`, `*`) та порівнянням валют.
* **`Product`** — сутність товару в каталозі. Здійснює перевірку ID, назви, об'єкта ціни `Money` та неподекуди від'ємного складського залишку (`quantity`).
* **`CartItem`** та **`Cart`** — структури для формування замовлення покупця. Забезпечують підрахунок підсумкової вартості (`total()`), знаходження найдорожчого товару (`get_most_expensive_product()`) та очищення кошика.
* **`PercentageDiscount`** — обчислювач відсоткової знижки із валідацією порогу `0..100%`.
* **`ProductRepository`** — каталог-репозиторій із функціоналом:
  - додавання та пошук за ID/назвою/категорією;
  - розрахунок вартості складських залишків (`get_total_inventory_value()`);
  - визначення товарів із критичним запасом (`get_low_stock_products()`);
  - імпорт даних із CSV-формату (з викиданням `MalformedRecordError` при бітих записах);
  - експорт каталогу в формат JSON.
* **`CheckoutService`**, **`PaymentGateway`**, **`Notifier`** — сервіси для проведення платежу. Зовнішні залежності `PaymentGateway` та `Notifier` абстраговані й тестуються за допомогою тестових подвійників (`Mock`).
* **`AsyncPaymentStatus`** — асинхронний провайдер для моделювання асинхронних транзакцій та завантаження даних за допомогою `AsyncMock`.

### 2. Стратегія тестування:
- **Unit тестування**: перевірка коректності створення об'єктів, валідації полів, межевих та некоректних значень (`boundary and invalid values`).
- **Мокування (Mocking)**: застосування `return_value` та `side_effect` для моделювання успішної оплати, відмови транзакції та мережевих збоїв.
- **Interaction Assertions**: перевірки викликів `assert_called_once_with`, `assert_not_called`, `assert_awaited_once_with`.
- **Ізоляція ФС**: використання фікстури `tmp_path` для тестування експорту файлів.
- **Асинхронні тести**: використання `@pytest.mark.asyncio` та `AsyncMock`.

## Опис реалізованих функцій та класів

| Клас / Метод | Призначення |
| :--- | :--- |
| `Money` | Клас для роботи з грошима, підтримує валідацію та операції додавання/віднімання/множення. |
| `Product` | Сутність товару з валідацією ID, назви, ціни та кількості. |

| `CheckoutService` | Сервіс проведення оплати із залученням `PaymentGateway` та `Notifier`. |
| `AsyncPaymentStatus` | Асинхронний сервіс для перевірки статусу оплати та віддаленого каталогу. |
| `export_order` | Запис вмісту кошика в JSON файл (з використанням `tmp_path` в тестах). |

### Перелік pytest фікстур та тестових сценаріїв:
1. `laptop`, `mouse`, `cart`, `catalog` — фікстури для створення тестового середовища.
2. `test_product_creation_and_validation()` — перевірка створення товару та викидання `InvalidProductDataError`.
3. `test_money_operations_and_boundary()` — перевірка арифметики `Money` та від'ємних сума/результатів.
4. `test_cart_operations()` — підрахунок total, знаходження max елемента та очищення кошика.
5. `test_percentage_discount()` — валідація відсотків знижки.
6. `test_catalog_search_and_filter()` — фільтрація за категорією, пошук за назвою, розрахунок залишків на складі та low stock.
7. `test_csv_import_valid_and_malformed()` — парсинг CSV та обробка пошкодженого CSV (`MalformedRecordError`).
8. `test_json_export()` — перевірка коректності структури JSON-експорту.
9. `test_checkout_service_success()` — успішна оплата з використанням `Mock` та перевіркою викликів.
10. `test_checkout_service_failure_path_side_effect()` — failure path оплати та моделювання помилок через `side_effect`.
11. `test_export_order_file()` — тестування збереження замовлення у файл через `tmp_path`.
12. `test_async_payment_status_and_flow()` — тестування асинхронного коду за допомогою `AsyncMock`.
